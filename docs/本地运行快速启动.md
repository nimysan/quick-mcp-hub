# mcp-hub 从源码本地运行：快速启动

适用于 `main` 分支，包含全部内置渠道（含飞书网页文档和本机邮件）。
不想自己构建的，直接用发布包，见 [`使用说明.md`](使用说明.md)。

每一步都分 **macOS / Linux** 和 **Windows** 两套命令。Windows 的步骤在 Windows Server 2025
（PowerShell 5.1、Go 1.27.4、Git for Windows 2.56）上实际跑通。

## 1. 准备

- Go 1.26.4 或更高（`go version` 查看）
- Git
- Amazon Quick 桌面版（或其他支持本地 MCP 的客户端）

Windows 默认没有 `make`，`plugins/build.sh` 也要 bash 才能跑。下面给的 Windows 命令都是 PowerShell 原生命令，
不需要 bash 和 make。

## 2. 拿代码并构建

**macOS / Linux**

```bash
git clone https://github.com/nimysan/quick-mcp-hub.git
cd quick-mcp-hub
plugins/build.sh                           # 先构建插件，否则测试会失败
make build                                 # 产物：dist/mcp-hub
```

**Windows（PowerShell）**

```powershell
cd $env:USERPROFILE
git clone https://github.com/nimysan/quick-mcp-hub.git
cd quick-mcp-hub

# 可选：proxy.golang.org 访问不了时用国内镜像（与 Makefile 默认一致）
# $env:GOPROXY = "https://goproxy.cn,direct"; $env:GOSUMDB = "sum.golang.google.cn"

# 1) 构建插件（等价于 plugins/build.sh）
New-Item -ItemType Directory -Force plugins\dist\ghwasm | Out-Null
$env:GOOS = "wasip1"; $env:GOARCH = "wasm"
go build -buildmode=c-shared -o plugins\dist\ghwasm\ghwasm.wasm .\plugins\ghwasm
Remove-Item Env:GOOS, Env:GOARCH
Copy-Item plugins\ghwasm\manifest.json plugins\dist\ghwasm\

# 2) 构建主程序（等价于 make build），产物：dist\mcp-hub.exe
$env:CGO_ENABLED = "0"
go build -trimpath -ldflags "-s -w -X main.version=0.1.0" -o dist\mcp-hub.exe .

dist\mcp-hub.exe -version                      # 打印 0.1.0 即构建成功
```

第一次构建要下载依赖，需要几分钟。产物大小参考：`ghwasm.wasm` 约 4.5 MB，`mcp-hub.exe` 约 20 MB。

已经装了 Git Bash 的，也可以在 Git Bash 里跑 `plugins/build.sh`，再用 `go build -o dist/mcp-hub.exe .` 代替 `make build`。

在 macOS 上交叉编译 Windows 版：

```bash
GOOS=windows GOARCH=amd64 go build -o dist/mcp-hub.exe .
```

验证（可选，两个平台命令相同；先完成插件构建）：

```bash
go vet ./...
go test -count=1 ./...
```

参考：Windows 上约 30 秒，21 个包 `ok`，5 个包没有测试文件。

## 3. 配置渠道

| 平台 | 打开配置页面 |
|---|---|
| macOS / Linux | `dist/mcp-hub -ui` |
| Windows | `dist\mcp-hub.exe -ui` |

会打开 http://127.0.0.1:7801（只监听本机，不对外）。

1. 添加需要的渠道，填凭据，点「测试并保存」。凭据存进系统的凭据服务（macOS 钥匙串、Windows 凭据管理器）；
   渠道配置在 Windows 上保存在 `%APPDATA%\mcp-hub\channels.json`。
2. 至少配一个渠道，否则 Quick 连不上。
3. 写操作（发信、建 Issue 等）默认关闭，需要时在「权限与工具」里打开。

**本机邮件（只读）**：在「内置渠道」里添加，勾选来源即可，不需要密码。

| 平台 | 来源 | 额外要求 |
|---|---|---|
| macOS | Apple Mail、旧版 Outlook、新版 Outlook | 给 **Amazon Quick** 授予「完全磁盘访问权限」（系统设置 → 隐私与安全性） |
| Windows | 经典版 Outlook（PST/OST）、新版 Outlook | 读经典版前要完全退出 Outlook；新版只能读离线缓存里的邮件（默认最近 30 天、离线设置里选中的文件夹） |

配完关掉页面，配置进程还会留在后台，需要手动结束：

- **macOS / Linux**：`pkill -f "mcp-hub -ui"`
- **Windows（PowerShell）**：只结束 `-ui` 进程。不要用 `taskkill /IM mcp-hub.exe`，它会把 Quick 正在用的 `-serve` 进程一起结束。

```powershell
Get-CimInstance Win32_Process -Filter "Name='mcp-hub.exe'" |
  Where-Object CommandLine -match '-ui' |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## 4. 接入 Quick

在 Quick 里：Customize → Connectors → Create → Add MCP → Local。

| 字段 | macOS / Linux | Windows |
|---|---|---|
| Command | `dist/mcp-hub` 的**完整路径**，例如 `/Users/me/quick-mcp-hub/dist/mcp-hub` | `mcp-hub.exe` 的**完整路径**，例如 `C:\Users\me\quick-mcp-hub\dist\mcp-hub.exe` |
| Arguments | `-serve` | `-serve` |

Arguments 只填 `-serve` 这一项，不加引号，也不用加别的参数。

也可以按 JSON 填写（Windows 示例，反斜杠要写成两个 `\\`）：

```json
{
  "mcpServers": {
    "mcp-hub": {
      "command": "C:\\Users\\me\\quick-mcp-hub\\dist\\mcp-hub.exe",
      "args": ["-serve"]
    }
  }
}
```

点 Test connection，成功后就能用。

试一句：「列出我的 GitHub 仓库」或「列一下我本机邮件的文件夹」。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| Quick 显示连接失败 | 确认至少配了一个渠道；Command 用的是完整路径 |
| 改了配置或换了程序，工具没变 | 在 Quick 里把 connector 关掉再打开 |
| 本机邮件提示没有权限（macOS） | 给 Amazon Quick 授完全磁盘访问权限，然后完全退出再打开 Quick |
| 经典版 Outlook 提示文件被占用 | 完全退出 Outlook（任务管理器里没有 OUTLOOK.EXE）再试 |
| 新版 Outlook 大多数文件夹显示 0 封 | 新版只缓存最近 30 天和离线设置里选中的文件夹，`total` 是本地缓存的封数 |
| `go test` 有一批用例失败 | 先完成第 2 节的插件构建（`plugins/build.sh` 或 Windows 的第 1 步） |
| Windows 上 `plugins/build.sh`、`make` 跑不了 | 用第 2 节的 PowerShell 命令 |
| Windows 上 Quick 突然连不上 mcp-hub | 检查是不是用 `taskkill /IM mcp-hub.exe` 结束了进程；按第 3 节只结束 `-ui` 进程，然后在 Quick 里把 connector 关掉再打开 |
| Windows 首次运行被 SmartScreen 拦 | 选「仍要运行」；程序未签名 |
