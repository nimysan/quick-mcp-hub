# MCP Hub 快速开始

把企业系统接到 AI 助手：一个程序，填一次账号密码，就能让 Claude、Cursor、
Amazon Quick 这类客户端读你的邮箱、GitHub、Jira 等系统。

**不需要安装 Python、Node 或任何运行时**，整个程序就是一个可执行文件。

---

## 一、先把程序放好

解压后把整个文件夹放到一个固定位置（之后客户端配置里要写它的路径，挪了就要改）。
建议：

- Windows：`C:\Program Files\mcp-hub\` 或 `D:\mcp-hub\`
- macOS / Linux：`~/Applications/mcp-hub/` 或 `~/mcp-hub/`

### Windows 第一次运行会被拦

这个程序没有做代码签名，所以 Windows SmartScreen 会提示「已保护你的电脑」。
点 **更多信息 → 仍要运行**。

### macOS 第一次运行会被拦

同样因为没有签名。在终端里对解压出来的文件夹执行一次：

```bash
xattr -dr com.apple.quarantine /path/to/mcp-hub
```

或者在 **系统设置 → 隐私与安全性** 里点「仍要打开」。

---

## 二、双击打开

双击 `mcp-hub`（Windows 是 `mcp-hub.exe`），会自动弹出一个配置窗口。

就这样，没有第二步。窗口关掉就停止；要再打开就再双击一次。

> 如果窗口没有自动弹出，在浏览器里打开 **http://127.0.0.1:7801** 就是同一个页面。
> 这个页面只在你自己的电脑上，同一个网络里的其他人访问不到。

---

## 三、填上你的账号

页面下半部分列出了可以连接的账号，点你要用的那个的「添加」。

常见的几类：

| 要连的 | 要填什么 |
|---|---|
| QQ / 163 / Gmail 等邮箱 | 邮箱地址 + **授权码**（不是登录密码，要到邮箱网页版的设置里生成） |
| GitHub | 用户名 + 个人访问令牌，或者点「连接」按钮授权 |
| Jira | 站点地址 + 邮箱 + API Token |

点「测试并保存」：程序会先真的连一次，**连不通就不保存**，所以保存成功就代表能用。

### 几件要知道的事

- **密码只进系统自带的密码保管箱**（Windows 凭据管理器 / macOS 钥匙串），
  不写进任何文件、不出现在日志里。
- **会改东西的功能默认关着**。发邮件、建 issue 这类，要手动勾「允许发信」/
  「允许写入操作」才会交给 AI。不勾的话 AI 根本看不到这些功能。
- 同一个系统可以配多个账号（两个邮箱、两个 GitHub），AI 用的时候指定哪一个。

---

## 四、接到 AI 客户端

客户端要知道主程序的**绝对路径**。不需要任何环境变量、不要在客户端里填密码 ——
账号和凭据都已经在本机了。

### Claude Desktop / Cursor / Cline 等

在它们的 MCP 配置里加一条：

```json
{
  "mcpServers": {
    "mcp-hub": {
      "command": "/绝对路径/mcp-hub",
      "args": []
    }
  }
}
```

Windows 的路径要把反斜杠写成双反斜杠：

```json
"command": "C:\\Program Files\\mcp-hub\\mcp-hub.exe"
```

### Amazon Quick

Customize → Connectors → Create local connector → 选 Local，
Command 填绝对路径，**Arguments 和 Environment variables 都留空**。

加完之后**点一次 Sync** —— Quick 不会自动刷新功能列表。

---

## 五、改了配置要让客户端重连

配置页面和 AI 服务是两个独立进程。AI 服务在启动时读一次配置，所以你在页面上
新增或修改渠道之后，要让客户端重新连接一次：

| 客户端 | 怎么重连 |
|---|---|
| Amazon Quick | Connectors 里把它关掉再打开，然后点 Sync |
| Claude Desktop / Cursor | 退出应用再打开 |

## 六、出问题时

```bash
mcp-hub -selftest        # 验证邮箱能否登录（不发信）
mcp-hub -list-secrets    # 列出已保存的凭据条目（不显示密码内容）
```

直接运行主程序（不带参数）时，它会把启动情况打在屏幕上：注册了哪些渠道、
多少个功能、哪些功能因为开关没开而没注册。看这几行通常就能定位问题。

### Linux 上的一个前提

凭据存在系统的 Secret Service 里（GNOME Keyring / KWallet）。服务器环境常常
没有装，这种情况下可以用环境变量兜底，具体见项目文档。

---

## 这个包里**没有**什么

- 没有任何账号、密码、令牌 —— 凭据只在你自己的机器上，由系统密码管理器保管
- 没有遥测、没有回传 —— 程序只连你自己配置的那些系统
